## スライド 1: タイトル

# 安否確認システム 概要

**自動架電による社員安否確認の仕組み**

2026年7月

---

## スライド 2: 背景と課題

# なぜ安否確認システムが必要か

- 災害発生時、社員300名の安否を迅速に把握する必要がある
- 従来の電話連絡網は**人手に依存**し、時間がかかる
- 担当者不在時に連絡が止まるリスクがある
- 結果の集計・報告も手作業で、全体像の把握に時間を要する

**→ 自動化により、迅速・確実・負担軽減を実現**

---

## スライド 3: システム概要

# 本システムでできること

1. **自動一斉架電**: ボタン一つで全社員に電話を自動発信
2. **音声による安否回答**: 社員は電話で「無事です」等と答えるだけ
3. **自動ステータス判定**: AI音声認識で回答を解析し、安否を自動分類
4. **リアルタイム集計**: 管理画面で全員の状況をリアルタイムに確認

---

## スライド 4: 主要機能

# 主な機能

| 機能 | 説明 |
|------|------|
| 社員管理 | 社員の登録・電話番号管理（CSV一括登録対応） |
| 自動架電 | 最大300名へ自動電話、つながらない場合は自動再発信 |
| 音声認識 | 回答内容をAIがテキスト化し、安否を自動判定 |
| ステータス確認 | 安全/負傷/対応不可/未到達を一覧で確認 |
| 折り返し対応 | 社員側から折り返し電話しても回答を受付 |
| キーワード辞書 | 判定精度の調整が管理画面で可能 |

## スライド 5: システム構成

# システム構成（簡略図）

```
    管理者（ブラウザ）
         │
    ┌────▼────┐
    │ 管理画面 │  ← クラウド配信（常時アクセス可）
    └────┬────┘
         │
    ┌────▼──────────┐
    │  AWS クラウド   │
    │                │
    │  ・自動電話機能 │  ← Amazon Connect
    │  ・音声認識    │  ← Amazon Transcribe
    │  ・データ管理  │  ← DynamoDB
    │  ・処理制御    │  ← Lambda + Step Functions
    └───────────────┘
         │
    ┌────▼────┐
    │ 社員電話 │  ← 自動着信 → 音声回答
    └─────────┘
```

- サーバーの管理不要（AWS がすべて管理）
- インターネット接続さえあれば管理画面にアクセス可能

## スライド 6: 利用の流れ

# 災害発生時の流れ

```
① 災害発生
    ↓
② 管理者がシステムにログイン
    ↓
③ 「安否確認開始」ボタンを押す
    ↓
④ システムが全社員に自動電話（最大10件同時）
    ↓
⑤ 社員が電話に出て「無事です」と回答
    ↓
⑥ AIが音声を認識し安否ステータスを判定
    ↓
⑦ つながらない社員には自動で再発信
    ↓
⑧ 管理画面でリアルタイムに状況を確認
```

**所要時間目安**: 300名に対し、初回発信完了まで約30分

## スライド 7: コストと技術面

# コスト・技術的特徴

**コスト構造**:
- サーバーレス構成 → **使った分だけ課金**
- 災害がない平常時のランニングコストは極めて低い
- サーバー保守の人件費ゼロ

**技術的な安心**:
- AWSの高可用性インフラ上で稼働（複数データセンター）
- データは暗号化して保管（個人情報保護）
- 録音データは90日で自動削除（コンプライアンス）
- 管理者のみがアクセス可能（認証・権限管理）
